Not a CLAUDE.md — short, opinionated, written for a future LLM picking up mid-task. Re-read at start of every session.

## Context
Aeocha is a BDD-style test framework for Aether, featuring `describe`, `it`, `before_each`, and `after_each` syntax. It's the primary test framework for Aether projects.

## Development Principles
- **BDD Syntax**: Follow the `describe` and `it` pattern. `it_within(name, budget) callback {}` is a timed `it` — fails if the body exceeds a `Duration` budget; it and `it()` share `_it_impl(_ctx, desc, fn, budget_ns)` (budget 0 = untimed).
- **Framework Context (ambient since 3a)**: `init()` returns a `fw` context AND stashes it in a module-level `current_fw` cell. Matchers (`assert_*`/`expect_*`/`fail` and the fluent chain) take NO `fw` — they read `current_fw`. Only the *structural* calls still take `fw`: top-level `describe(fw, name)` (no enclosing block to auto-inject a `_ctx`) and `run_summary(fw)`; nested `describe`/`it`/`before_each`/`after_each` auto-inject the suite `_ctx`. Tradeoff: **one framework per process** — a second `init()` rebinds `current_fw`. Enabled by Aether's mutable module globals + module-var-shared-across-imports (#937, 0.328). (The old "`fw` threaded through every call" rationale is gone — Aether no longer rejects mutable module-level state.)
- **Integration Matchers**: Maintain the `expect_*` matchers for process and HTTP testing. These are designed to be high-level and reduce boilerplate in integration tests. Two HTTP layers exist: *low-level* (`expect_http_status`, `expect_http_body_eq`, `expect_http_body_contains`, `expect_http_header`, `expect_http_body_json_field`) take a `resp` the caller builds/frees; *high-level* (`expect_http_get_status`, `expect_http_get_body_eq`, `expect_http_get_body_contains`) do the GET + request/free lifecycle themselves so a test asserts a response in one line. The high-level ones reuse the low-level ones internally. Note `send_request` already frees `resp` and returns null on transport error — the error branch must NOT `response_free`. `expect_http_header` uses the `client.response_header` wrapper (snapshot-safe via `string.copy`, upstream #269), NOT the raw `http_response_header_raw` extern — the raw form aliases a thread-local buffer the next call clobbers.
- **Process matchers — stdout vs stderr**: stdout matchers (`expect_stdout_contains`, `expect_stdout_matches`, etc.) consume `os.run_capture`'s output. For child *stderr*, use `os.run_full(prog, argv, env, stdin) -> (stdout, stderr, exit, err)` (separate-stream capture, no pipe deadlock) and feed its 2nd slot to `expect_stderr_contains` / `expect_stderr_empty`. Don't confuse run_full's `stderr` slot (child fd 2) with `run_capture`'s third slot (spawn-error string, consumed by `expect_no_spawn_error`).
- **Pattern matchers — glob vs regex**: `expect_stdout_matches` is glob-only (`std.string.glob_match`, no extra deps). `expect_stdout_matches_regex` is full PCRE2 via `std.regex` (unanchored, per-line). regex requires `libpcre2-8` at runtime; if absent, every entry returns a clean error via the `(ok, err)` slot — the matcher treats a non-empty `err` as a loud failure (so a missing-lib env fails, not silently passes). Use glob where libpcre2 may be absent.
- **Timing & Duration**: Per-`it()` timing uses `os.now_monotonic_ns()` (NTP-jump-free) for the elapsed delta — NOT `clock_ns()` (wall clock, can step mid-run). `init()` stamps the run-start monotonically too; the aeb-report total must use the same clock or the delta is garbage. `expect_elapsed_under(fw, elapsed_ns, budget: Duration, msg)` takes a plain int64 ns span the caller measures and a `Duration` literal budget (`50ms`). Aether's `Duration` (issue #524) is a distinct type: `Duration`-vs-plain-number is a type error, so bridge via the `.ns` accessor (`elapsed_ns < budget.ns`). `${duration}` interpolation renders the largest readable unit (`50ms`, `1.5s`) — fixed in ae 0.325.0 (was #927). Future timing helpers (`it_within`, `eventually`, `within`/`without`) are in TODO.md §Timing.
- **Fluent facade**: Alongside the flat `assert_*`/`expect_*` matchers there's a subject-first chainable layer — `expect_int(x).to_equal(5).to_be_gt(0)`, `expect_str(s).to_contain("foo")`, `not_()` to negate. Built on UFCS (a `.to_*` is a free fn whose 1st param is the subject; aether #934) + an ambient `current_fw` module-`var` set by `init()` (aether #937 — module-var shared across imports), so the chain carries no `fw`. Requires **ae 0.328+** (both fixes). Each `.to_*` returns the subject for chaining and reports via `fail(current_fw, ...)`. Int matchers are unsuffixed, string ones carry a name (`to_equal_str`) — Aether has no receiver-type overloading. **Single-framework caveat**: reads `current_fw`, so it asserts against the last `init()`; use flat matchers to drive two frameworks at once. When editing, always `rm -rf ~/.aether/cache` AND test a FAIL path (the happy path never reads `current_fw`, so it masks a broken ambient cell — this exact gap produced false-green ghosts during development).
- **Floating modifier (`within`/`without`)**: `within(5s)` sets an ambient retry budget that the NEXT `expect_http_get_*` matcher consults — it polls the GET (every 50ms, or `within_poll(5s, 100ms)`) until the condition holds, or the budget elapses, then the budget auto-reverts (one-shot, positional — "doesn't last beyond the operation to its right"). `without(5s)` is the inverse: poll until the condition stops holding. No budget set → matchers are single-shot exactly as before. Implemented via module-`var` budget cells (`long`, not int — #929) + an internal silent probe `_http_get_probe` that the retry driver loops; the public matchers never see the loop. Use this instead of a magic `sleep(N)` to wait for a server to bind (the probe's HTTP section does). **Generic `eventually(pred, msg)` shipped** (0.329): polls a zero-arg predicate `fn` under the same ambient `within`/`without` budget the GET matchers use (no budget → one eval). Unblocked once bare-fn-into-`fn`-arg worked across modules (#940) *and* inside closures (#943) — both fixed in 0.329. Gotcha baked into the code: `_take_retry_budget()` resets ALL of budget/poll/without (not just budget), and callers snapshot poll/without BEFORE calling it — else a no-`within` matcher after a `without()` inherits the stale flag and inverts.
- **Custom matchers**: a matcher is just a fn that calls `fail(msg)` (no base class, no registration, no fw — `fail` reads ambient `current_fw`). Aeocha's own matchers are written this way, so user matchers are first-class. Failures accumulate (soft-assert): `fail` records and continues. Escape hatch: `expect_int(x).satisfies(pred, msg)` / `satisfies_str` run an arbitrary `fn(value)->1/0` mid-chain. Collection matchers (`expect_list_size/empty/has_str`) operate on a `std.list` of strings (int lists omitted — raw list stores ptrs, would need a boxing convention). **Gap**: extending the *fluent chain* with a new `.to_*` only works inside the module declaring the subject — `IntSubject`/`StrSubject` are exported but Aether can't name a qualified type (`aeocha.IntSubject`) in another module's signature yet (would be the next upstream ask for true cross-module fluent extension). Hamcrest-style matcher-as-a-value combinators (`allOf`/`anyOf`) are a deliberate non-goal for now — soft-assert covers most of the need (just write several `expect_` calls).
- **No upward deps in tests**: Aeocha is the lowest-level test framework in the stack — its own tests must not depend on downstream projects. The HTTP-matcher probe uses a plain in-process `std.http` server (hand-rolled routes), NOT `servirtium-vcr` (VCR moved out of the aether stdlib into the standalone `servirtium-vcr` project, imported as `core.vcr`; don't reintroduce `std.http.server.vcr`).
- **IPC Reporting**: `run_summary` emits a structured v1 report if it detects a parent IPC channel (e.g., when run by `aeb`). Durations are nanoseconds (4e): the it-record stores `duration_ns_str`, the header carries both `duration_ms=` (v1 compat, may round to 0) and `duration_ns=` (full precision), and per-row duration is ns. Stays `version=1` and wire-compatible — the row consumer matches STATUS/index/name/message and ignores the duration value, so widening ms→ns is safe. When touching the format, keep `duration_ms=` present or you break existing parsers.

## Building / Testing
- **Compiler**: Uses system-wide `ae`. Developed/verified on **v0.328.0**, which is now the practical floor — the fluent facade needs cross-module UFCS (#934, fixed 0.327) and module-`var` shared across imports (#937, fixed 0.328). Earlier dependencies: `Duration` (`expect_elapsed_under`, ~v0.19x), `os.run_full` (stderr matchers, v0.231), `std.regex` (v0.191), plus the 0.325 fixes `${duration}` interpolation (#927) and the module-`var` narrowing guard (#929). Older notes (`std.strbuilder` v2 since v0.161, `string.char_at_n`) still hold but are well below the floor.
- **Include Path**: When testing locally, set `AETHER_INCLUDE_PATH` to the repo root to use the local `aeocha.ae`.
- **STALE CACHE — bites hard**: `~/.aether/cache` does NOT invalidate when an imported module's source changes. After editing `aeocha.ae`, the next `ae run` of any test silently keeps running the *previously compiled* `aeocha` — edits, even syntax errors, are ignored. Always `rm -rf ~/.aether/cache` after touching `aeocha.ae`, or you will debug a ghost.
- **Integration Tests**: Run `./tests/integration/aeocha_aeb_ipc_reporting/test_aeocha_aeb_ipc_reporting.sh` etc.
- **Bootstrap**: Use `./bootstrap_aether.sh` to fetch and build Aether locally if not installed.

## Files/dirs worth knowing
- `aeocha.ae`: The core framework implementation and Aether-facing surface.
- `tests/integration/`: Integration tests that exercise process and HTTP matchers.
- `tests/regression/`: Regression tests for compiler features that Aeocha exercises.
- `example_self_test.ae`: A good starting point for seeing how to use the framework.

## Idioms that keep biting
- **Trailing Blocks**: Use the trailing block pattern for `describe`.
- **Closure Capturing**: Be mindful of closure capturing rules in Aether when using hooks.
- **Detached server hangs the process**: A test that spins up an in-process `std.http` server runs it on a detached actor thread that never returns. `run_summary` only `exit(1)`s on failure, so on success the process hangs holding its port — next run fails to bind. End `main()` with an explicit `exit(0)`.
